# Social Events — Frontend

Next.js 16 front end for **Social Events**, a site where anyone can list their upcoming events (blood donation drives, tree plantations, community cleanups, …).

Events are served by the Express API in [`../backend`](../backend).

## Stack

| | |
|---|---|
| Framework | Next.js `16.4.3` (App Router) |
| UI | React `19.3.0`, TypeScript (strict) |
| Styling | Tailwind CSS v4 via `@tailwindcss/turbopack` |
| Lint | ESLint 9 + `eslint-config-next` |

## Getting Started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

The backend API must be running for data to load — see [`../backend/README.md`](../backend/README.md).

## Project Structure

```
src/
├── app/
│   ├── layout.tsx      # Root layout, fonts, metadata
│   ├── page.tsx        # Home page
│   ├── globals.css     # Tailwind entry point
│   └── favicon.ico
└── components/         # (optional) shared UI
```

- **Path alias** — `@/*` maps to `./src/*`.
- **Routing** — App Router under `src/app`. `layout.tsx` uses the generated `LayoutProps<"/">` global type; don't redeclare it.

## Configuration

- `next.config.ts` enables `cacheComponents` and `partialPrefetching`. Keep new routes and segments compatible with cache components — don't pull in uncached dynamic data without an explicit cache boundary.
- Tailwind v4 is wired through the Turbopack CSS loader; global styles live in `src/app/globals.css` (`@import "tailwindcss";`).
- Env vars are read from `.env.local` (see `.env*` in `.gitignore`). Point the app at the API with something like:

  ```bash
  NEXT_PUBLIC_API_URL=http://localhost:8000
  ```

  Read it from the env rather than hardcoding the backend host in components.
